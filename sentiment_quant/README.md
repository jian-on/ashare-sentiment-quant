## 数据源架构：为什么东财会一直限流

| | 东财（旧方案） | 腾讯（现方案） |
|---|---|---|
| 全A快照 | 59 页分页请求 | **12 批批量请求，约 1 秒** |
| 单只K线 | 0.5s 强制节流 → 150只需 75 秒 | **4 线程并发，150 只约 5 秒** |
| 一次扫描总请求 | 200+ 次 | **约 15 次**（5分钟内重扫全命中缓存） |
| 结果 | 必被 IP 限流，5-40 分钟 | 正常使用不触发 |

**根本原因**：东财是"逐只拉取"，150 只候选池必须发 150 次请求，这跟调参数没关系，
是架构决定的。腾讯支持批量查询，请求数降一个数量级，才是真正的解法。
东财保留为备源（failover），不再是主链路。

### 三级保护机制（防止把自己玩死）
1. **缓存优先**：快照 60 秒 / K线 5 分钟 TTL，重复点击几乎零请求
2. **源健康状态**：某源被拦截后自动进入冷却（腾讯 3 分钟 / 东财 3 分钟），
   冷却期内**直接跳过不发请求**——这是关键，之前反复点击会把封禁从 5 分钟拖到 40 分钟
3. **WAF 熔断**：腾讯连续 15 只失败判定为整体拦截，立即中止整批而非硬扛

### 接口实测记录（2026-11-05 实盘）
```
qt.gtimg.cn 批量行情      HTTP 200，499 只 0.11s，字段含现价/涨跌幅/换手率/量比/总市值/涨停价
web.ifzq.gtimg.cn 前复权K线  HTTP 200，121 根 0.09s，含当日盘中K线
全市场 5574 只          26 批 → 0.7s（建立 active_codes.txt 后降至 12 批）
K线 120 只              4 线程 → 5s
```
**腾讯也有 WAF**（返回 501 跳转 waf.tencent.com），阈值远高于东财，
但短时间内连续跑多次全量扫描仍会触发。触发后需冷却 10-30 分钟。

```
PY="C:/Users/27553/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
$PY sources.py                # 数据源烟测（快照+K线）
$PY sources.py --debug        # 打印原始字段，接口变更时排查
$PY data_loader.py            # 数据层烟测
$PY market_sentiment.py       # 温度计（本地计算）+ 财联社快讯
$PY watchlist.py --codes 002384,600519
$PY recommend.py --top 10 --pool 120   # 横截面排序观测
$PY make_launcher.py          # 重新生成启动器

# 每日收盘后积累 point-in-time 存档（回测证据的唯一来源）
# ★ 已配置定时任务：交易日 15:50 自动执行下面第一条，无需人工干预
$PY backtest.py --daily                   # 交易日判定 → 存档 → 补标签 → 状态（一站式）
$PY backtest.py --label-pending           # 只补齐所有可补标签（幂等，可重复跑）
$PY backtest.py --status                  # 查看准备度（探索期 30 日 / 验证期 245 日）
$PY backtest.py --quality [N]             # 最近 N 日数据质量摘要（默认 5，异常自动列告警）
$PY backtest.py --report                  # 正式样本外报告（需 245 日，不足明确拒绝）
$PY backtest.py --report --preview        # 30 日探索性诊断（EXPLORATORY_ONLY，不判 PASS/FAIL）
# 手动补档（正常不需要）：$PY backtest.py --archive / --label 20261106
# 盘中强制复盘（风险自负）：$PY backtest.py --archive --force
```

**盘后流水线口径**（2026-11-13 定死，改动会导致存量样本全部作废）：
- 存档落在 `data_cache/pit/YYYYMMDD.parquet`，**不可变**，日志 `data_cache/pit/daily_run.log`（均被 `.gitignore` 排除）。
- `--daily` 用腾讯快照行情日期判定交易日：休市日**跳过存档**，绝不把上一交易日快照按新日期存成重复截面；补标签在休市日照常执行。
- 标签口径：清单 T 日收盘后才生成 → **T+1 开盘买入、T+5 收盘卖出**。用 T 日收盘价当成本等于假设能回到过去成交，会系统性高估收益。
- T+1 一字涨停（主板 10cm / 创业板科创板 20cm 分别判定）视为买不到，剔除而非假装成交；单日标签覆盖率 ≥80% 才计为已标注。
- 补标签由脚本扫描存档自行判断 T+5 是否到来，**不需要人工推算交易日历**，法定长假不会漏补。
- **双基准**：`fwd_excess_5d` 减候选池等权（衡量排序能力），`fwd_excess_mkt_5d` 减中证全指
  `sh000985` 同窗口 T+1 开盘→T+5 收盘（衡量真实超额，**主判定用这个**）。报告拆成
  「选池贡献 / 打分贡献 / 总超额」三段，避免把选样收益误认成打分能力。
- **收盘闸门**：本地时间早于 15:00 一律拒绝写 PIT 存档（自动/手动路径都拦），
  防止补跑或手动执行把盘中未定型 K 线永久固化。确需盘中复盘用 `--archive --force`。
- **schema 版本隔离**：存档带 `pit_schema_version`（当前 3），回测面板与补标签只认当前版本。
  11-13 那份 v1 存档留在磁盘但自动排除，不与新口径混用。
- **数据质量留痕**：每份存档写入 `quality_json`（asof 一致性、有效权重、失效因子、舆情覆盖率/来源）
  与 `board`（10cm/20cm）。`--quality` 读最近 N 日并自动列异常；`--daily` 日志也会打当日告警。
- **选样口径冻结**：`当日成交额分 5 层等额抽样（seed=42）`。这是设计选择而非 bug——
  T 日收盘后生成清单，T 日成交额此时已知，T+1 开盘买入，不构成未来函数。
  改 T-1 的 20 日均额需先建全 A 历史成交额基线且易触发 WAF，收益不足以打断样本积累，故推迟。
- **两级样本口径**：探索期 30 日、验证期 245 日，两者职责严格分离。

| | 探索期 | 验证期 |
|---|---|---|
| 门槛 | 30 个已标注交易日 | 245 个已标注交易日（120+60+60+5） |
| 命令 | `--report --preview` | `--report` |
| verdict | `EXPLORATORY_ONLY` | `PASS_OOS` / `FAIL_REVERT_TO_BASELINE` |
| 分段 | 不切三段，取最近 30 日整体诊断 | purged walk-forward + 段间 5 日 embargo |
| 能否据此调权 | ❌ 绝对不能 | ✅ 仅 PASS 后，且 OOS 只看一次 |
| 能否宣称有效 | ❌ 不能 | ✅ 唯一口径 |

为什么不能把 245 改成 30：T+5 标签有 5 日未成熟期，段间还有 2×5 日 embargo，
30 日窗口实际可用截面不足 20；而门槛 `ICIR≥0.30` 且 `p<0.05` 要求
`t = 0.30×√20 ≈ 1.34` 才可能显著（实际需 >1.96），**数学上永远不可能同时满足**。
探索窗口与正式 OOS 重叠，探索结果不得作为独立证据。
