```

sentiment    std = 0.0000   ← 0.25 权重（最高）完全空转
```

## 三、✅ 已修复的确定性 bug

| # | 问题 | 位置（修复前） | 修复 |
|---|---|---|---|
| B1 | `pos_in_20d` **双重反向**：`stock_factors` 已用 `1-(close-min)/rng` 把方向统一为「低位=高分」，`score_pool` 又做 `1 - winsorize_z(...)`，变成高位加分，与 5 日反转因子互相打架 | `factors.py:36,90` | 改为直接 `winsorize_z`，均值回归 0 |
| B2 | **舆情选择偏差**：先按无舆情分取 Top10，再只对这 10 只补舆情重排 → 权重最高的舆情因子永远无法影响「谁入选」 | `recommend.py:46-58` | 舆情前置到 60 只确定性候选集，集内全量补分后同一横截面一次成榜 |
| B3 | `sentiment` **量纲混加**：原始分 ∈(-1,1) 且集中在 ±0.1~0.3，直接与 z 分数加权，最高权重实际贡献被压到 1/5 以下 | `factors.py:96` | 横截面 `winsorize_z` 后进入 |

| B6 | `market_beta` **截面常数**：同一天所有股票同值，不改变排序，只让 composite 跨日漂移、不可比 | `factors.py:97`, `config.py:39` | 移出权重表，保留列仅供诊断 |

| B10 | **过期数据绕过严格实时**：非限流异常/空数据分支无条件 `return old`，可返回 11 天前的 K 线，无任何标记 | `data_loader.py:254-257` | 受 `ALLOW_STALE_FALLBACK` 约束，否则返回 None |
| B11 | 温度计**时点错配 + 静默降级**：允许 1 小时缓存快照；全接口失败时算式返回 -0.3「偏空」却标成正常读数；涨停判定用比例容差，高价股误差 0.22 元 | `market_sentiment.py:63-67,92` | 打分与温度计复用同一 spot；绝对 0.01 元 tick 容差；备源按 10/20cm/ST 分阈值；全 0 时返回中性并打 `DEGRADED` 标记 |

## 五、⚠️ 新增但**默认关闭**的实验项

### 市场状态自适应权重（`regime.py`）

四个状态（冰点/回暖/高潮/退潮），判定只用温度计已有字段（market_score、涨停/跌停家数、炸板率、涨跌家数），权重表按 A 股动量-反转混合结构调整：高潮期压反转加动量量能，退潮期压反转/位置/量能、把低波动提到 0.28 防守。阈值刻意粗粒度、权重取 0.05 整数倍，避免细网格过拟合。

**`config.ENABLE_REGIME_ADAPT = False` 默认关闭**。理由来自风控角色的明确反对：在没有任何历史截面面板时增加自由度，属于无法证伪的改动。开启前必须完成下面的检验；当前 UI 只显示观测到的状态名，不据此调权。

### point-in-time 存档 + purged walk-forward（`backtest.py`）

补齐了 README 里长期标记为「待开发」、且 `config.py` 中 `COMMISSION / SLIPPAGE / TRAIN_DAYS / VALID_DAYS / OOS_DAYS` 长期零引用的缺口：

- `--archive`：收盘后把当日完整横截面落盘为**不可变**快照（因子 z、composite、状态、舆情源）
- `--label YYYYMMDD`：T+5 后用项目自有腾讯K线补未来 5 日超额标签，零付费 API
- `--report`：TRAIN 120 / VALID 60 / OOS 60，段间 5 日 embargo 防标签重叠泄漏；输出 Rank IC、ICIR、IC>0 占比、t 值、TopN 扣费净超额，并分市场状态检验
- **判定门槛**：OOS 需同时满足 IC>0、ICIR≥0.30、IC>0 占比≥55%、p<0.05、扣费净超额>0，否则 `FAIL_REVERT_TO_BASELINE`

需要 ≥245 个已标注交易日。当前 0 天，`--report` 返回 `INSUFFICIENT_DATA` 并**拒绝给出任何有效性结论**。

**每日积累命令**（收盘后）：
```bash
python backtest.py --archive
python backtest.py --label <5个交易日前的YYYYMMDD>
python backtest.py --status
```

## 六、遗留问题（未修，如实列出）

1. **盘中未收盘 K 线**：腾讯日K末根是盘中动态值，收盘后运行无影响，盘中会让反转/位置/量能因子随价格漂移，且回测用收盘价 → 回测与实盘口径不一致。
2. **舆情新闻无时点过滤**：`sentiment.py` 按 `sort=default` 取单页 ≤50 条，未用 `time` 字段做旧闻过滤或时间衰减，短线情绪因子混入数月乃至数年前旧闻。一旦做历史回测即构成 look-ahead，必须先按发布日期落库才能重放。
3. **舆情样本量小且跨股不可比**：股吧源已失效，只剩个股新闻，媒体口径偏理性；无 `DASHSCOPE_API_KEY` 时走规则词典，`RULE_BASED` 与 `QWEN` 分不能混用在同一次检验里。
4. **分层抽样仍是当日成交额分层**：虽已缓解"只选蓝筹"，但仍用当日结果选样；更严谨需用 T-1 的 20 日平均成交额。
5. **20cm / 10cm 混池**：创业板与科创板纳入后涨跌幅限制不同，反转/量能因子的分布会混合，需在回测里按板块分层检验。
6. **部分 K 线失败会静默缩池**：现只打警告，横截面 z 在残缺池上重算仍会失真。

## 七、盘后自动化与标签口径（2026-11-13 18:40 追加）

### 为什么必须现在做
第六节的结论是「任何权重调整都不可证伪，除非攒够 245 个已标注交易日」。人工每天跑命令不可持续，
且 `--archive` 用 `date.today()` 命名，**周末会把上一交易日快照存成新日期**，制造重复截面、
虚增面板天数，最终让 walk-forward 的统计显著性完全失真。自动化不是便利功能，是证据链成立的前提。

### 已落地
- 定时任务「因子模型 · 盘后 PIT 存档与标签补齐」，交易日 15:50，下次运行 2026-11-16（周一）。
- `backtest.py --daily`：交易日判定（腾讯快照 `asof` 行情日众数）→ 不可变存档 → 幂等补标签 → 状态。
  解析不出行情日一律跳过存档（宁可漏一天，绝不存错截面）；休市日跳过存档但仍补标签。
- `--label-pending` 扫描存档自行判断 T+5 是否到来，不需人工推算交易日历，法定长假不会漏补。
- 日志 `data_cache/pit/daily_run.log`；任务被明确禁止修改模型代码、造数据、或在数据不足时给结论。

### 同时修正的标签口径 bug（必须在攒数据前定死）
原实现用 **T 日收盘价**作买入成本，但参考清单是 T 日收盘后才生成的，最早只能 T+1 开盘成交 ——
等于假设能回到过去成交，会系统性高估收益。若先攒 245 天再发现，全部样本作废。
现改为 **T+1 开盘买 → T+5 收盘卖**；T+1 一字涨停按板块（主板 10cm / 创业板科创板 20cm）
判定为买不到并剔除；放弃「全部非空」的完成判定，改用 ≥80% 覆盖率，否则只要一只标的缺失
就会永远 pending、每天重复拉取 60 次 K 线。

### 验证
- **2026-11-13 18:43 实盘 `--daily`**：21 秒，存档 60 只、状态「退潮」、退出码 0，
  落盘 `data_cache/pit/20261113.parquet`（asof 2026-11-13 18:43:22，收盘后）。
- 离线构造 K 线单测：T+1 开盘买收益 0.089109 与手算一致、主板一字涨停剔除、
  20cm 板不误剔、覆盖率达标、重跑幂等跳过 —— 全部 PASS。
- 交易日判定单测：今日 True / 上一交易日 False / 脏数据与空表均 False。

### 仍然成立的限制
定时任务只解决「证据从哪来」，不解决「证据够不够」。当前 **1 天存档 / 0 天已标注 / 需 245 天**。
`--report` 在此之前返回 `INSUFFICIENT_DATA`；自动化提示词已明令禁止在数据不足时给有效性结论。

## 八、风险与免责

- 本项目是**横截面因子相对排序观测**，不是涨跌预测，不是荐股。高分 ≠ 会涨。
- 本报告所有权重与阈值均为**待验证假设**，未经样本外回测，不得据此实盘或对外宣称有效。
- 题材/舆情类因子拥挤度高、天然容易失效；A股短线还受交易成本、冲击成本、涨跌停无法成交等约束，`COMMISSION_MIN` 对小资金影响尤其大。
- 本文所有行情数据来自腾讯批量接口，标注时间为 2026-11-13 17:50、18:00 与 18:43（北京时间，均为收盘后）。
