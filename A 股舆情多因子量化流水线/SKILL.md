# 技能名称：A股舆情多因子量化流水线
## 技能描述
用于开发、迭代、调试基于 Streamlit + AKShare 的A股题材情绪多因子选股原型。
仅用于学习研究、回测验证，**严禁生成任何实盘买卖建议，不预测股价涨跌**；只做标的筛选、行情清洗、舆情情感识别、因子打分、回测评估。

> 本文件是 2026-11-13 至 11-16 多智能体审计后沉淀的**强制执行规矩**。
> 每次涉及本项目的量化任务都会加载本文件：以下约束优先于任何"先做个好看的结果"的诉求。

---

## 一、绝对红线

1. 不得输出"买入/卖出/建议仓位/目标价/明天会涨"等实盘指令。输出只能是横截面相对排序的观测。
2. 不得用未来数据。任何在 T 日收盘后才知道的信息，只能用于 T+1 及之后的交易决策。
3. 不得在样本不足时给出有效性结论。数据不够时只能返回 `INSUFFICIENT_DATA`，不能"先给个大概结论"。
4. 不得为了让结果好看而改口径、改分段、改阈值。口径变更必须显式升版本并声明旧样本作废。

---

## 二、行情数据时点（最高优先级铁律）

1. **所有行情数据必须标注时间**。每个快照要带 `asof`（上游行情日期/时间），K 线要带最后的交易日。
   没有时间标注的数据视为不可用，不能用"应该是最新的"代替。
2. **严格实时**：`ALLOW_STALE_FALLBACK = False`。任何源都失败时直接报错，绝不静默返回过期缓存。
   过期缓存冒充实时，比报错危险得多。
3. **前置校验**：同一横截面内所有标的的 `asof` 必须是同一交易日且时间跨度合理；不一致就在
   `quality_json` 里标 `asof_ok=false` 并列入告警，不能直接拿去算 z-score。
4. **盘中禁写**：本地时钟早于 `ARCHIVE_MIN_HHMM`（15:00）一律拒绝写不可变存档。
   腾讯日 K 末根在盘中是动态值，写进去就永久污染当日截面。只有显式 `--force` 才能绕过。
5. **K 线过期判定**：不能用"文件存在"判断可用，要比对最后一根 K 的交易日；过期且无兜底时该股不进池。
6. 前复权校验：主动检查复权错位（同一日不同源的收盘价比例异常），发现即停。

---

## 三、标的过滤与选样

1. 强制剔除：ST/*ST、退市预警、上市未满 60 日新股、停牌、日均成交额过低的流动性差标的、北交所。
2. 创业板 `300/301` 与科创板 `688` 是 A 股题材短线主线，**不得静默过滤**（历史上曾因正则只认 60/00/688 被全量剔除）。
3. 选样口径一旦确定必须**冻结贯穿整个样本期**。当前口径：当日成交额分 5 层等额抽样，固定 `seed=42`。
   - 用"当日成交额"选样在 T 日收盘后执行、T+1 开盘买入，**不是未来函数**，只是"偏当日活跃股"的设计取舍。
   - 改成 T-1 的 20 日均额需重建全 A 历史基线且易触发上游 WAF，收益不足以打断样本积累。
4. 分层抽样是为了避免只选到大盘蓝筹；不要为了"结果更好"改成 top_amount。
5. 板块分层：按代码前缀标记 `20cm`（300/301/688）与 `10cm`。只用于诊断，不据此自动调权。

---

## 四、舆情 NLP 规范

1. 文本来源：个股财经新闻（股吧源已失效，不要再依赖）。文本先降噪：去广告、去重复灌水。
2. **时点过滤是硬要求**：
   - 按"发布日期"而非"抓取顺序"参与打分；无发布日期的文本一律丢弃。
   - 剔除未来新闻（超过上游时钟容差 `NEWS_FUTURE_TOL_MIN` 分钟）。
   - 剔除超过 `NEWS_MAX_AGE_DAYS`（10 天）的旧闻；按 `NEWS_HALF_LIFE_DAYS`（3 天）半衰期加权。
   - 新闻明细按日期落盘，供历史重放。
3. **舆情必须前置到候选集**：先取 `SENTIMENT_COVERAGE_N` 只确定性候选，在集内全量补舆情后重排。
   绝不能"先取 Top10 再只对这 10 只补舆情"——那是选择偏差，舆情从不影响谁入选。
4. 不同来源必须分组标准化：`RULE_BASED`（词典）与 `QWEN`（模型）的分数不可混用在同一检验里。
5. 调用大模型做情感打分时，**强制输出纯 JSON，禁止多余文字**，结构固定：
   ```json
   {
       "sentiment": 0.0,
       "theme": "无",
       "is_noise": false
   }
   ```

## 五、因子构建与诊断

1. 因子方向统一为"分越高越好"。改方向前先确认没有双重反向（`pos_in_20d` 曾犯过这个错）。
2. 计算的是横截面因子，**同一截面内为常数的因子权重为 0**（`market_beta` 曾占 0.50 权重却恒等于常数，等于把半个模型扔掉）。
3. 算了却没进权重字典的因子是死代码，要么启用要么删除（`vol_trend` 曾如此）。
4. 横截面处理后做 winsorize（分位截断）+ z-score 硬截 ±3；零方差因子剔除后**有效权重必须重归一**，
   并在诊断里记录 `effective_weight_total` 与 `dropped_factors`。
5. 组内样本 <5 时 z 无统计意义，记中性，不要制造虚假离散度。
6. 所有权重都是**待验证假设**，不是"回测优化出来的最优参数"。没有样本外证据不得调权。
7. 市场状态自适应权重（`regime.py`）默认关闭，只观测不调权；开启前必须通过样本外检验。

## 六、Point-in-time 存档（证据链的地基）

1. 每个交易日收盘后把完整横截面（因子 z、composite、状态、舆情源、质量诊断）落盘为**不可变快照**。
   存档一旦写入不得修改；口径变更只能新增版本文件。
2. `schema` 版本隔离：`v1`/`v2`/`v3` 文件保留在磁盘供审计，但旧版本**不进回测面板、不再补标签**。
   否则会形成"旧因子值 + 新收益标签"的混杂面板，且无法区分。
3. 口径任何变更（数据源、排序、标准化、选样、字段含义）必须 `PIT_SCHEMA_VERSION += 1`，
   并在变更说明里写清"存量样本是否作废"。
4. 补标签幂等：用覆盖率（≥80%）而非"全部非空"判定某日是否标注完成，
   否则一只一字涨停缺失就会永远 pending、每天重复拉取。
5. 数据质量看板每日留痕：`asof` 一致性、有效权重、失效因子、舆情覆盖率、板块分布。
   K 线部分失败会让横截面 z 在残缺池上重算——不报错，但会毁掉证据，只能靠质量看板发现。

## 七、回测口径

1. **标签**：T 日收盘生成清单 → **T+1 开盘买入 → T+5 收盘卖出**。
   - 禁止用 T 日收盘买入，那是假设能回到过去成交，会系统性高估收益。
   - T+1 一字涨停买不到，按 10cm/20cm 涨跌幅精确判定后剔除。
   - 最后 5 个交易日标签未成熟，不能算作已标注样本。
2. **双基准，缺一不可**：
   - 候选池等权 → 衡量**排序能力**（IC 用池内相对收益 `fwd_excess_5d`）。
   - 固定外部基准中证全指 `sh000985` → 衡量**真实市场超额**（净超额用 `fwd_excess_mkt_5d`）。
   - 只用池内基准会掩盖"整个候选池都跑输市场"的情况。
3. **三段归因**必须可加：总超额 = 选池贡献（池等权 − 市场）+ 打分贡献（TopN − 池等权）。
   报告中要输出 `identity_check`，误差应 <1e-5。
4. 成本：双边佣金 + 双边滑点 + 卖出印花税，扣费后的净超额才是可讨论的收益。
5. `purged walk-forward`：TRAIN / VALID / OOS 时序切分，段间 embargo 5 日防标签窗口重叠泄漏。
   OOS **只看一次即冻结**，不得反复试参数。

---

## 八、统计显著性与两级样本口径

1. **50 个截面以下的 ICIR / p 值没有统计效力**，不要拿来做"模型有效"的结论。
2. 两级口径（2026-11-16 确立）：
   - **探索期 30 个已标注交易日**：只输出描述性诊断，verdict = `EXPLORATORY_ONLY`。
     不判 PASS/FAIL，不得据此调权或对外宣称有效。必须在报告里写清"与正式 OOS 重叠、不构成独立证据"。
   - **验证期 245 个已标注交易日**（TRAIN 120 + VALID 60 + OOS 60 + EMBARGO 5）：
     唯一可给出有效性结论的口径。判定门槛全部满足才算 PASS：
     `IC>0`、`ICIR>=0.30`、`IC>0 占比>=55%`、`p<0.05`、扣费净超额>0，否则 `FAIL_REVERT_TO_BASELINE`。
3. **不要把 245 简单改成 30**：30 日扣 embargo 与未成熟标签后不足 20 个截面，
   `t = 0.30×√20 ≈ 1.34`，永不可能同时满足 `ICIR>=0.30` 与 `p<0.05`，
   验证会退化成"必然失败"的假证据。缩短等待的正确方式是增加探索期，不是降低正式门槛。
4. 分市场状态 / 分板块检验：单组样本 <20 个截面时标注"不单独定参，回退基准权重"。
   两板块 IC 反向时回退基准，**不自动按板块调权**——没有样本外证据就增加自由度就是过拟合。
5. 过拟合自检：正式结论前必须回答"我是不是试了 20 种参数才挑出这组"。
   参考 CPCV / DSR（夏普缩水）/ PBO（回测过拟合概率）方法，不要只看单次 OOS。

## 九、交付前自检清单

每次改动后逐条确认，缺一条就不算完成：

- [ ] 全量编译通过（`python -m compileall` 或等价检查）
- [ ] 所有行情有 `asof`，截面时点一致，数据质量看板无新增告警
- [ ] 没有未来函数：清单 T 日收盘后生成，买入 T+1 开盘
- [ ] 因子方向、量纲、零方差、有效权重重归一都检查过
- [ ] 口径变更多了就升 schema 版本，并说明旧样本是否作废
- [ ] 双基准与三段归因都在报告里，`identity_check` 误差 <1e-5
- [ ] 样本不足时明确返回 `INSUFFICIENT_DATA` / `EXPLORATORY_ONLY`，没有给出有效性结论
- [ ] 验证全程没有盘中运行 `--daily` 污染不可变存档
- [ ] 文档（README / RESEARCH）与代码口径一致
- [ ] 提交消息说清改了什么、是否影响存量样本
